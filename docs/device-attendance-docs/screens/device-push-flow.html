The URL already carries everything the device needs — the address, this device's token, and its name. There is no port or protocol to set separately.
⚠
That URL is a password. Anyone holding the token can post attendance into your company. Don't paste it into tickets, screenshots or chat. If it leaks, press Regenerate token — the old URL stops working immediately and the terminal must be reconfigured.
✽

Before you leave the device

🕐
Set the clock (NTP). A terminal with an unset clock stamps events 1970-01-01. Attendance would be booked in 1970 and the employee reads absent today, forever.
🔒
A real certificate is required. These terminals reject self-signed certificates and fail silently — nothing appears on their screen.
👤
Enrol faces at the terminal. With no route back to the device, Maugood cannot push photos to it. Faces and fingerprints are enrolled on the device itself.

Because we never connect to the terminal, its people are discovered from the events themselves. The first time someone taps, Maugood records the device ID and the name shown on the device, then tries to match it to an employee code automatically.

Maugood never creates an employee from a device. An unrecognised ID is parked, never auto-enrolled — the same rule the photo importer follows. If a real person is missing, add them in Employees first, then map.

A post with no employeeNoString is a keepalive. We answer 200 and record liveness only — it never creates an attendance row. Unknown employee, bad clock or duplicate also get 200; any other reply makes the terminal retry in a loop. Only an unknown or revoked token is refused.
