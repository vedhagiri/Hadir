6. HOW in_time / out_time ARE CALCULATED
   Convert UTC->IST, sort by time, take FIRST + LAST tap. direction label is IGNORED.

┌───────┬──────────────────────┬─────────────┬───────────────────┐
│ event │ occurred_at (UTC)    │ IST (local) │ role              │
├───────┼──────────────────────┼─────────────┼───────────────────┤
│ 5001  │ 2026-08-03 03:42:00Z │ 09:12       │ first  = in_time  │
├───────┼──────────────────────┼─────────────┼───────────────────┤
│ 5002  │ 2026-08-03 07:30:00Z │ 13:00       │ middle (ignored)  │
├───────┼──────────────────────┼─────────────┼───────────────────┤
│ 5003  │ 2026-08-03 08:15:00Z │ 13:45       │ middle (ignored)  │
├───────┼──────────────────────┼─────────────┼───────────────────┤
│ 5004  │ 2026-08-03 13:00:00Z │ 18:30       │ last   = out_time │
└───────┴──────────────────────┴─────────────┴───────────────────┘
   in_time = 09:12 | out_time = 18:30 | total = 558 min.
   Break (13:00->13:45) is NOT deducted -> total is the full span. (confirm break-deduction with manager)

7. DUPLICATE PROTECTION (per employee, per day)

┌─────────────────┬──────────────────────────┬──────────────┬─────────────────────────────────────────┐

├─────────────────┼──────────────────────────┼──────────────┼─────────────────────────────────────────┤

   N taps per day -> N events -> 1 attendance row. Never double-counts.
