### C. Reference-image validation — single contract for all upload paths
Commit: **`75cd681`** · Migration `0070`

One enforced contract on both frontend (UX) and backend (authoritative) across **four** ingest paths (employee edit drawer, bulk folder upload, employee self-upload, map-unidentified-face → employee):

| Rule | Detail |
|------|--------|
| Cap | Max 10 reference images per employee |
| Type | JPG/JPEG/PNG/WEBP only — by **magic-byte sniff** (extension/content-type untrusted) |
| Size | `MAUGOOD_EMPLOYEE_PHOTO_MAX_MB` (default 10MB) |
| Dedup | SHA-256 of plaintext bytes; duplicates rejected per employee |

- Backend helpers in `maugood/employees/photos.py`: `sniff_image_ext`, `validate_image_bytes`, `count_photos`, `photo_hash_exists`, `content_sha256`.
- Frontend shared util `src/util/photoValidation.ts` (107 lines).
- Migration `0070` adds `employee_photos.content_sha256` + dedup index (schema-agnostic).
- Tests: 3 new (type rejection, duplicate, 10-cap), 2 existing updated; 9 passed.

### D. Camera bulk Import / Export
Commit: **`b51ba3b`** (the work done in this session)

- **Export** selected or all cameras to JSON; optional `?ids=` query param.
- **Import** with dry-run preview (`/api/cameras/import-preview`) and per-row apply (`/api/cameras/import`).
- Modes: `update` (default) or `skip` for code matches.
- Pure decision-matrix classifier (`maugood/cameras/transfer.py`, ~250 lines): `create | update | skip | error` per row.
- Per-row transactions on apply; one bad row doesn't roll back successful ones.
- Hot-reload hooks fired after commit (`capture_manager.on_camera_created/updated`).
- **Security tradeoff (explicit operator choice):** export carries the full plaintext RTSP URL inline. Audit rows + logs still record `rtsp_host` only. Treat the JSON file as a secret.
- 19 new tests; full camera suite 29 pass.
